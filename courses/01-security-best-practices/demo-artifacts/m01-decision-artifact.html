Globomantics · Recovery architecture decision record

Customer-order data protection

Asset: Azure Blob Storage, order documents
Business criticality: High · RTO 40 h stated · RPO 24 h
In place Recommended Gap, unaddressed
Requirement Control Why this control answers it Status
Recover from accidental deletion Operational backup on the storage account Point-in-time restore, soft delete, versioning, change feed, delete lock. Fast, because the data never moved. In place
Survive a compromised administrator Blob vaulted backup in a Backup vault Copies the data offsite into storage Azure Backup manages. Operational backup stays on the account the attacker controls. Recommended
Recovery points cannot be deleted Vault immutability, enabled then locked Set at the vault, enforced across every protected instance in it. Locked adds WORM and is irreversible. Recommended
No single admin can weaken protection Multi-User Authorization with a Resource Guard Shortening retention or disabling soft delete needs a second approver the first cannot overrule. Guard sits in a separate subscription. Recommended
The 40-hour tolerance is real Timed restore test, to an alternate account Vaulted restore targets a different storage account, so the recovery plan has to account for that before the incident, not during it. Gap
Backup operators are not standing admins Just-in-time privileged access Phase two work. Raises the cost of stealing a credential; does not stop the admin who legitimately holds one. Gap
Architectural finding

Globomantics protects this data against deletion, not against an attacker. Operational backup lives on the account a compromised administrator already controls, and the 40-hour tolerance has never been measured. Fund vaulted backup with immutability and multi-user authorization first, then test the restore against the stated RTO.
