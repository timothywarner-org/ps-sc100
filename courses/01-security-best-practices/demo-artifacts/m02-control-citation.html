The recommendation, with its receipts

IM-1 Use centralized identity and authentication system MCSB v1 · GA
Security principle. Use a centralized identity and authentication system to govern your organization's identities and authentications for cloud and non-cloud resources. Azure guidance. Standardize on Microsoft Entra ID to govern identity and authentication for Microsoft cloud resources, for your organization's own applications, and for enterprise identities synchronized from Active Directory, and avoid local authentication methods wherever the service supports Entra ID.

The recommendation

Extend centralized identity to the plant-floor scope. Control IM-1 in benchmark version 1 (GA) maps to NIST AC-2, passing on of assessed resources there against of in production. The gap is one scope, not one framework, and the auditor's NIST mapping came with the control rather than from a spreadsheet.

Sources, checked 2026-08-31. The control name, security principle, Azure guidance and framework mappings above are quoted from learn.microsoft.com/security/benchmark/azure/mcsb-identity-management#im-1, the MCSB v1 control page. v1 is generally available and is the standard assigned to this subscription; MCSB v2 is in preview, and its IM-1 carries a different name (“Centralize identity and authentication while ensuring isolation”) against different framework identifiers and different framework versions. That is why this card prints its benchmark version on its face. Naming note: the v1 page still writes “Azure Active Directory (Azure AD)”; the current product name is Microsoft Entra ID, and a document lagging a product name is exactly why you cite a control number and a version rather than a product name. Documentation inconsistency worth knowing: the v2 policy-mapping page, learn.microsoft.com/security/benchmark/azure/mcsb-v2-controls-policy-mapping#im-1, still heads IM-1 with v1's name, so even inside v2 the naming isn't settled. Scope of the claim: Microsoft's own caveat is that these mappings “only indicate that you can use specific Azure features to fully or partially address a security control requirement” and that such implementation “doesn't necessarily translate to the full compliance.” This card maps to those controls and contributes evidence toward them. It isn't proof of compliance.
