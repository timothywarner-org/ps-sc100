Clip 1·Objective 4.1.1

Microsoft 365 posture and the Globomantics Copilot rollout

Secure Score measures the controls you've adopted, not how likely a breach is, so read it as a to-do list before you widen a Copilot rollout. Start with Microsoft Learn's unit on evaluating security posture for productivity and collaboration workloadsREAD FIRSTLEARN, then read Assess your security posture with Microsoft Secure Score to see how the current license score separates work you can finish today from work that needs a purchase. Clip 2·Objective 4.1.2

Evaluate Defender for Office 365 and Defender for Cloud Apps

Pick the Defender for Office 365 plan by how your SOC works, because Plan 1 prevents and Plan 2 adds investigation and response. Read Microsoft Learn's unit on Defender for Office 365 and Defender for Cloud AppsREAD FIRSTLEARN first, then the Defender for Office 365 overview for what each plan includes. In Defender for Cloud Apps, a person working inside an app and an app calling an API need different controls, so compare session policies, which govern what a user does inside a session, with app governance, which governs what OAuth apps can reach. Shadow AI belongs in the same evaluation, and Manage generative AI apps for your organization shows how to govern the generative AI apps people bring in on their own.

Clip 3·Objective 4.1.3

Evaluate device management with Microsoft Intune

An Intune compliance policy only marks a device, and Conditional Access does the enforcing. Read Microsoft Learn's unit on how Intune protects and manages endpointsREAD FIRSTLEARN, then the Conditional Access grant controls, including Require app protection policy, which protects corporate data on a personal phone without enrolling it.

Clip 4·Objective 4.1.4

Evaluate Microsoft Purview for Microsoft 365 data

Classify first, then protect the item and the path it travels. Start with Microsoft Learn's unit on securing Microsoft 365 data with PurviewREAD FIRSTLEARN, then settle who holds the key. Customer Key leaves Microsoft 365 services able to process your content, while Double Key Encryption means Microsoft can never decrypt it, so search, eDiscovery and Copilot can't use it either. Use Microsoft Purview to manage data security and compliance for Microsoft 365 Copilot shows what that choice means for Copilot.

Clip 5·Objective 4.1.5

Evaluate Copilot data security and compliance controls

Microsoft 365 Copilot answers only from what a user can already open, so it creates no new access and surfaces whatever oversharing already exists. The Learn unit on Copilot data security and compliance controlsREAD FIRSTLEARN anchors objective 4.1.5. Microsoft renamed the app, so read the Microsoft Copilot overviewRENAMED to recognize both names, and Microsoft Copilot requirements for what has to be in place first. Data, Privacy, and Security for Microsoft Copilot explains why Copilot honors the usage rights on encrypted content. Then work through the controls: data loss prevention for the Microsoft 365 Copilot location, data risk assessments that find overshared sites, SharePoint Advanced Management, which comes with a Copilot license, and Restricted Content Discovery, which hides a site from Copilot while you fix its permissions. Restricted SharePoint SearchRETIRING is retiring, so learn it only as a distractor. For the interactions themselves, read Audit logs for Copilot and AI applications.

Clip 6·Objective 4.1.5, 4.1.4 DEMO

Demo: Trace a Copilot answer to the files behind it

The demo proves Copilot surfaced a file the user could already open, which supports fixing access at the source instead of pulling licenses. Copilot interactions land in the audit log with no extra setup, as Audit logs for Copilot and AI applicationsREAD FIRST explains, and you find them with Search the audit log. The Copilot interaction events overview documents the fields you read in the record, including the files the answer drew on. So why could the user open the file? On a public group-connected site, the default SharePoint groups give Everyone except external users edit access, and the Everyone except external users article shows where that claim sits. The file's label shows in the library's Sensitivity column, which Enable sensitivity labels for files in SharePoint and OneDrive and Configure a default sensitivity label for a SharePoint document library both cover. The faded pass opens a data risk assessment and asks which overshared site you'd fix first.

Clip 7·Objective 4.1.5

Check the answer against the Copilot location in Purview data loss preventionREAD FIRST and the considerations for managing Microsoft 365 Copilot for security and compliance, and see why Restricted Content Discovery fails once the site's other files should stay available to Copilot. Clip 2·Objective 4.2.2

Model threats to a business-critical application

Threat modeling analyzes a design before code exists, when a fix costs a whiteboard instead of a rewrite. Read Evaluate application threats with threat modelingREAD FIRSTLEARN for STRIDE across every element and trust boundary of a data flow diagram, and Getting started with the Threat Modeling Tool for how the tool generates candidate threats from that diagram. Clip 4·Objective 4.2.3

Design a full lifecycle application security strategy

A lifecycle strategy puts a security activity at every stage and keeps one requirement traceable from the backlog to the runtime evidence. Design a full lifecycle strategy for application securityREAD FIRSTLEARN covers recorded risk acceptance, static and dynamic testing, artifact catalogs, and an emergency release path that shortens approval but still runs its tests. Clip 5·Objective 4.2.4

Set standards for the secure development process

A standard only counts where something enforces it, and this objective is thin in the free Learn path, so give it extra time. Design and implement standards to secure application developmentREAD FIRSTLEARN covers the Security Development Lifecycle and the DevOps Security controls in the Microsoft cloud security benchmark, and the Cloud Adoption Framework governance unitLEARN places them in a DevSecOps process. Then match each control to its stage. Push protection blocks a push, code scanning merge protection blocks a merge through a ruleset, and both belong to GitHub Advanced Security. At the build, the Microsoft Security DevOps GitHub action and Azure DevOps extension run their analyzers as one pipeline task. Agentless code scanningPREVIEW reads your repositories outside the pipeline and can't break a build. DevOps security support and prerequisites shows which features need Defender CSPM, including code-to-cloud mapping, and the workload identities unitLEARN covers pipeline sign-in through workload identity federation instead of a stored secret. The portfolio unitLEARN closes the loop by routing a runtime finding back to the team that owns the code.

Clip 6·Objective 4.2.4

Clip 2·Objective 4.2.6

Design workload identities for Azure access

Where the workload runs decides the identity: a managed identity on Azure, workload identity federation for a workload outside Azure such as a GitHub Actions pipeline, and a service principal with a secret only as the last resort. Start with Secure access for workload identitiesREAD FIRSTLEARN, then Configure a user-assigned managed identity to trust an external identity provider for the federated credential and its subject. Clip 3·Objective 4.2.7

Design API management and security

API Management is the policy enforcement point for every API Globomantics publishes, and this objective is thin in the free Learn path. Read Design a solution for API management and securityREAD FIRSTLEARN first, then the policies themselves: rate-limit-by-key, validate-content, and the transform tutorial, which strips headers that reveal your stack. Placement follows who calls the API, and since trusted service connectivityRETIRED retired, you design the gateway's network path to its backends explicitly. The API Management FAQ confirms the gateway has no web application firewall of its own, so put a firewall in front of it and restrict the gateway to your Front Door. Microsoft Defender for APIs watches REST APIs published through API Management, and its support and prerequisites and its FAQ settle what's in scope.

Clip 4·Objective 4.2.8

Design and tune Azure Web Application Firewall

Pick the firewall by where it inspects, then tune it from evidence. Clip 1·Objective 4.3.1

Data discovery and the Globomantics formulation data

Discovery comes before any other data control, because you can't protect data you haven't found. Read Evaluate solutions for data discovery and classificationREAD FIRSTLEARN, then compare the scopes. The Microsoft Purview Data Map scans across Azure, other clouds and on-premises sources and holds metadata only, while Data Discovery and Classification in Azure SQL classifies columns inside one database. The Globomantics formulation data sits in Azure SQL, Azure Storage and Azure Cosmos DB, so the module's later units on threat prioritiesLEARN, encryptionLEARN, Azure workloadsLEARN, Defender for Storage and Defender for DatabasesLEARN and AI workloadsLEARN each pick up one part of it. Document-level access control in Azure AI Search sets up the AI index question the module closes on.

Clip 2·Objective 4.3.2

Specify priorities for mitigating threats to data

Order matters: classification comes first, and customer-managed keys come last as the only data protection control rated should have rather than must have. Read Specify priorities for mitigating threats to dataREAD FIRSTLEARN, then the criticality ratings in the benchmark's Data Protection controlsPREVIEW. Those ratings live in version 2 of the Microsoft cloud security benchmarkPREVIEW, which is in preview, while version 1 is generally available, so cite the version whenever you cite a control. Mapping the threats you actually face reorders the middle of the list, moving exfiltration controls up when exfiltration is the main risk, and classificationLEARN still stays first.

Clip 3·Objective 4.3.3

Evaluate encryption with Azure Key Vault and Managed HSM

The deciding question in encryption at rest is who controls the key that protects the data keys. Read Microsoft Learn's unit on encryption at rest and in transitREAD FIRSTLEARN, then How to choose the right Azure key management solution and Key management in Azure to compare platform-managed keys, customer-managed keys in Key Vault, and Azure Key Vault Managed HSM, the single-tenant option. Infrastructure encryption adds a second layer under a Microsoft-managed key, and you can only turn it on when you create the account, a point the Azure Storage unitLEARN makes too. For virtual machines, Azure Disk Encryption is scheduled for retirementRETIRING, so new designs use encryption at host.

Clip 4·Objective 4.3.5

Secure data in Azure SQL, Azure Synapse, and Azure Cosmos DB

Each database protects data differently, and dynamic data masking isn't a security boundary at all. Start with Design data security for Azure workloadsREAD FIRSTLEARN. Transparent data encryption protects Azure SQL files at rest, while Always Encrypted keeps the keys on the client, so even database administrators can't read the values, and dynamic data masking only masks values in query results. For Azure Synapse Analytics, a managed virtual network with data exfiltration protection limits outbound traffic to approved tenants, and you choose it when you create the workspace. Azure Cosmos DB uses data-plane role-based access with Microsoft Entra ID, with local authentication turned off.

Clip 5·Objective 4.3.6

Secure data in Azure Storage

An account that still accepts Shared Key authorization gives full data access to anyone who can list its keys, so turn Shared Key off. Design security for Azure StorageREAD FIRSTLEARN covers the whole design, and Prevent Shared Key authorization for an Azure Storage account explains what disallowing it rejects and why a user delegation SAS keeps working. Authorize access to data in Azure Storage adds that Conditional Access on a storage account requires Shared Key to be off, and immutable storage covers records that must never change.

Clip 6·Objective 4.3.7

Select Defender for Storage and Defender for Databases

Identity controls stop the caller who isn't allowed, and Microsoft Defender for Storage watches the one who is. Read Microsoft Learn's unit on Defender for SQL and Defender for StorageREAD FIRSTLEARN, then What is Microsoft Defender for Storage for activity monitoring and sensitive data threat detection, and Introduction to malware scanning for scanning on upload. Microsoft Defender for Databases is a family of separately priced plans, and the Azure Cosmos DB plan covers the API for NoSQL only.

Clip 7·Objective 4.3.4

Design security for data used in AI workloads

An AI retrieval index inherits whatever oversharing its sources carry, so you fix permissions at the source before you index. Design security for data used in AI workloadsREAD FIRSTLEARN is the starting point. Document-level access control in Azure AI Search reproduces source permissions at query time, and it can't correct them. Data risk assessments show which sites to fix first, and Microsoft Purview for Microsoft Foundry extends audit, labels and data loss prevention to Foundry. Query-time sensitivity label enforcement in Azure AI SearchPREVIEW is still in preview, so check its status before you design around it.

Clip 8·Objective 4.3.6, 4.3.7 DEMO

The demo shows whether the assistant's data path is keyless and monitored, and it supports the fixes Globomantics makes before the assistant reaches more customers. Clip 9·Objective 4.3.3

Practice question and key points

The practice item asks how to make one customer's data unreadable on demand at the lowest cost, so a customer-managed key in Key Vault Standard wins: disable the key, and every read of that account fails. Customer-managed keys for Azure Storage encryptionREAD FIRST shows the mechanism. How to choose the right Azure key management solution and Key management in Azure show why Managed HSM is strength the item never asked for, even though Managed HSM's control model is what a single-tenant mandate needs. Infrastructure encryption runs under a Microsoft-managed key, so it leaves nothing for Globomantics to disable.
